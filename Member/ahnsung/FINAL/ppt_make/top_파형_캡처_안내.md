## 0. 한눈에 보기

UART 명령은 24 종이지만, Top 안에서 디코더 · 컨트롤러를 지난 뒤 나가는 길은 **4 갈래**뿐입니다. 갈래마다 대표 1 개, 그리고 센서 오류 2 장면을 더해 모두 6 장면입니다.

| 장면 | 보여주는 것 | 대표하는 명령 (같은 경로) | 시뮬 길이 | 캡처 수 |
|---|---|---|---|:-:|
| **P1** | `/mod dist` : 스위치에서 UART 로 화면 제어권이 넘어감 | `/mod` 8 종, `/set`, `/off` (경로 ① 화면 제어) | 26 ms | 2 |
| **P2** | `/btn R` : UART 버튼 → SR04 trig → 123.0 cm → `/get` → `123cm` | `/btn` 4 종 (경로 ③), `/get` (경로 ②) | 48 ms | 3 |
| **P3** | `/auto all` : **실제 1 Hz** 로 SW → TM → WH → DIST → TEMP 5 줄 | `/auto` 7 종 (경로 ②, 전송 MUX 입력 5 개) | 5.2 s | 3 (+ 확대 5) |
| **P4** | `/gxt` : 형식 오류 → ERROR 1 줄 → 뒤 명령은 정상 | 형식 오류 10 종 (경로 ④) | 36 ms | 3 |
| **P5** | SR04 `Err1` 무응답 · `Err2` 범위 밖 · `Err3` echo 고착 → FND + PC + LD9 | 센서 오류 (v2) | 258 ms | 7 |
| **P6** | DHT11 측정 전 `--%--C` · `Err1` 응답 없음 · `Err2` 중간 끊김 · `Err3` 체크섬 | 센서 오류 (v2) | 5.05 s | 9 |

**시간을 줄이지 않았습니다.** 100 MHz, 9600 baud, `/auto` 1 Hz, 센서 1 us tick, DHT11 부팅 1 s · 측정 간격 2 s 모두 보드와 같습니다. 따라서 파형의 시간 간격이 곧 실제 시간입니다. (기존 그룹 TB 는 `FAST = 1` 로 `/auto` 를 200 Hz 로 줄였기 때문에 발표용으로 따로 만든 것입니다.)

## 1. 실행

### 1-1. 명령창 (Windows, `FINAL\sim_file` 에서)

```
run_present.bat P1 wave      :: P1 만 + xsim GUI 에 P1.wcfg 파형 (run all 까지 자동)
run_present.bat P3 wave
run_present.bat P5           :: 파형 없이 콘솔만 → xsim_work\tb_P_present\sim_P5.log
```

- **장면은 하나씩 돌리세요.** 그래야 장면 시작이 0 ms 가 되고, 아래 표의 시각과 그대로 맞습니다.
- **시뮬은 한 번에 하나만** 돌리세요 (동시에 돌리면 PC 가 매우 느려짐).
- **P3 · P6 은 시뮬레이션 시간이 5 초**입니다 (100 MHz × 5 s = 5 억 클럭). 몇 분에서 수십 분까지 걸릴 수 있으니 P1 · P2 · P4 · P5 를 먼저 끝내세요.
- 파형을 처음 열면 그 장면의 **overview 구간**으로 확대된 상태입니다. Vivado 가 Zoom Fit 으로 바꿔 버리면, 아래 표의 구간으로 다시 확대하세요.

### 1-2. Vivado GUI 로 할 때

1. Simulation Sources 에 `tb_merge_harness.sv` + `tb_P_present.sv` 를 넣고, `tb_P_present` 를 *Set as Top* 합니다.
2. *Settings > Simulation > Simulation* 탭의 `xsim.more_options` 에 `-testplusarg only_P3` 처럼 장면을 지정합니다.
3. `xsim.view` 에 `wcfg/present/P3.wcfg` 를 지정 → Run Simulation → Run All.

### 1-3. 콘솔에서 꼭 확인할 것

```
[  14.3215 ms] [MARK   ] /mod dist  @ 5.0000 ms          ← 단계 시작
[  14.3720 ms] [OK     ] P1-2  after /mod dist | ...     ← 판정 (OK / FAIL)
[  26.0000 ms] [CAPTURE] P1-B   13.2333 ~ 14.4215 ms ... ← 캡처 구간 (실제 이벤트로 계산)
...
  CAPTURE windows (...)                                   ← 마지막에 캡처 구간을 모아서 다시 출력
[SUMMARY] P_present checks=.. fail=0 => PASS
```

> **아래 표의 시각은 계산값(≈)입니다.** 수신 바이트 완료 시점이 baud tick 에 맞춰 ±10 us 정도 흔들립니다. 따라서 **실제 캡처는 콘솔 마지막의 `CAPTURE windows` 값을 쓰세요.** 표는 미리 보기용이고, 콘솔 값과 0.1 ms 이상 차이 나면 이상한 것입니다.

## 2. 시간 기준 (계산 근거)

| 항목 | 값 | 비고 |
|---|---|---|
| UART 1 글자 (PC → FPGA, 8N1) | 10 bit × 104.17 us = **1.0417 ms** | TB 가 글자를 쉬지 않고 이어서 보냄 |
| 수신 완료 (`w_rx_done`) | 글자 시작 + 약 0.99 ms (9.5 bit) | 마지막 글자의 rx_done → 몇 clk 뒤 `w_handshake` |
| `/mod dist` 9 글자 · `/auto all` 9 글자 | 9.375 ms | handshake ≈ 시작 + 9.32 ms |
| `/btn R` 6 글자 · `/get ⏎` 6 글자 | 6.25 ms | handshake ≈ 시작 + 6.2 ms |
| FPGA → PC 줄 길이 | 시간 `00:00:01.09⏎` 13 글자 = **13.54 ms**, `123cm⏎` · `Err 1⏎` · `ERROR⏎` 7 글자 = **7.29 ms**, `55%24C⏎` · `--%--C⏎` 8 글자 = **8.33 ms** | |
| `/auto` 주기 | `sender_tick_generator` 100,000,000 clk = **1.000 000 s** | `/auto` 를 받은 뒤부터 셈 → 첫 줄 = handshake + 1 s |
| SR04 | trig 11 us, echo 대기 30 ms (Err1), 최대 echo 23.2 ms (Err2), 고착 50 ms (Err3 = trig↓ + 73.2 ms), 측정 주기 60 ms | TB 센서 모델 : trig↓ + 0.5 ms 뒤 echo |
| DHT11 | 부팅 1 s, 시작 LOW 18 ms, 측정 간격 2 s (이전 시작 기준), 응답 없음 판정 0.23 ms, 끊김 판정 0.2 ms | 버튼은 간격 안에 누르면 기억했다가 2 s 가 되면 측정 |

### 캡처 요령

- **파일 이름 = 캡처 ID** (예 : `P3-A.png`). 저장 위치는 `ahnsung/FINAL/ppt_make/wave_img/` 입니다. PPT 를 만들 때 이 이름으로 찾습니다.
- 구간 확대 : 파형 영역에서 **왼쪽 → 오른쪽으로 드래그**하면 그 구간으로 확대됩니다. 또는 커서를 놓고 Zoom In 을 누르세요.
- 시간 재기 : 첫 지점에 커서를 놓고 *Add Marker* 를 누른 뒤, 두 번째 지점을 클릭하면 Δ 시간이 보입니다. **"정확히 1.000 s" 를 보여 줄 장면(P3-G)에서는 꼭 마커 두 개를 찍어서** 캡처하세요.
- ASCII 신호 (`W_STEP` · `W_CMD` · `W_LINE` · `FND_DATA`) 는 값 칸이 좁으면 글자가 잘립니다. 확대하거나 Value 열을 넓히세요.
- 색 : 하늘색 = PC 명령 · tx/rx, 노랑 = 핵심 결과, 초록 = 센서 핀, 빨강 = 오류 신호.
- **`W_RX`** = 받은 글자. `w_rx_done` 순간 값만 잡아 둔 것입니다. `uart_rx` 의 `o_rx_data` (`w_rx_data`) 는 시프트 레지스터라 비트마다 밀려서 중간값 (`x` `^` `@` …) 이 보이므로 쓰지 않습니다.
- **디코더 상태** : `DEC_STATE` = `UART_ASCII_DECODER` 의 `c_state` 이름 (`IDLE` → `SLASH` → `m` → `o` → `d` → `SPACE` …), 옆에 숫자 `c_state` (0 ~ 14) 와 모은 옵션 글자 `w_ascii` (`dist`) 도 있습니다.
- **FND** (위 → 아래 = 신호 흐름)
  - `w_clk_4khz` : 4 kHz tick (100 MHz × 25,000 clk 마다 1 clk 펄스, 250 us 간격) → `w_scan_sel` 0 ~ 7 (한 바퀴 2 ms)
  - `fnd_com` → **`FND_COM`** : 지금 켜진 자리 `AN0` ~ `AN3` (`1110` = AN0, `1101` = AN1, `1011` = AN2, `0111` = AN3). 250 us 마다 AN0 → AN1 → AN2 → AN3 → (점 차례) AN0 → … 로 돕니다.
  - `fnd_font` → **`FND_FONT`** : 그 순간 켜지는 실제 글자 `{숫자, 점}` (`c0` → `0`, `7f` → ` .` 점만, `ff` → 빈칸). 핀과 같은 시각에 바뀝니다.
  - 읽는 법 : `FND_COM` 과 `FND_FONT` 를 같은 칸끼리 위아래로 읽으면 "AN3 에 `1`, AN2 에 `2`, AN1 에 `3`, AN0 에 `0`" 처럼 자리별 표시가 됩니다 (scan 0 ~ 3 = 숫자, 4 ~ 7 = 점 차례).
  - `w_fnd_data` (hex) → `FND_DATA` : Top 의 FND 데이터 MUX 출력을 **보이는 값으로** 바꾼 것 (`123.0` · `55.24` · `----` · `Err1` · 시계 `SS.CC` / `HH.MM`). 데이터가 바뀌는 그 clk 에 바로 바뀝니다.

### P3 `/auto all` — 실제 1 Hz (경로 ② 송신, 전송 MUX 입력 5 개)

**준비 단계 (0 ~ 110 ms)** : 줄마다 다른 값이 나오도록 먼저 움직여 둡니다.

| 시각 (ms) | 명령 | 효과 |
|---|---|---|
| 1 | `/mod s_ms` | 스톱워치 화면 |

| **100 ~ 109.375** | **`/auto all`** | handshake **≈ 109.32 ms** |

**1 Hz 송신 (계산값, 콘솔 NOTE 로 확인)**

| 줄 | `w_send_go` (ms) | `o_send_sel` | tx 구간 (ms) | `W_LINE` (예상) |
|:-:|---|:-:|---|---|
| 1 | ≈ 1109.32 | 0 SW | 1109.32 ~ 1122.86 | `00:00:01.09` (±0.01) |
| 2 | ≈ 2109.32 | 1 TM | 2109.32 ~ 2122.86 | `00:00:57.94` (±0.01) |
| 3 | ≈ 3109.32 | 2 WH | 3109.32 ~ 3122.86 | `12:00:03.10` (±0.01) |
| 4 | ≈ 4109.32 | 3 DIST | 4109.32 ~ 4116.61 | `123cm` |
| 5 | ≈ 5109.32 | 4 TEMP | 5109.32 ~ 5117.65 | `55%24C` |

- **`GO_GAP_US` = 1,000,000 · `GO_GAP_CLK` = 100,000,000** — send_go 간격을 TB 가 클럭 단위로 센 값입니다. 2 번째 줄부터 이 값이 뜹니다. 정확히 1 Hz 라는 증거입니다.
- `U_CONTROL/w_clk_5hz` (이름은 5hz 이지만 1 Hz 로 설정) 펄스 → 다음 clk 에 `w_send_go` 가 나옵니다.
- 시간 값 3 개를 보면 1 s 마다 실제 시간이 흘렀다는 것도 맞습니다 : 스톱워치 1.09 s → (1 s 뒤) 타이머 57.94 s → (1 s 뒤) 시계 3.10 s.
- tx 줄 시작 간격은 1.000 s ± 6.5 us 입니다 (tx 비트가 baud tick 에 맞춰지므로). send_go 간격은 정확히 1.000 000 s 입니다.
