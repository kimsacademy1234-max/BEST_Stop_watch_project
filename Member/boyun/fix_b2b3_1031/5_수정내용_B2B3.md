## 1. 무엇이 문제였나 (한 줄)

센서 모듈은 **값**과 **상태 (정상 · 오류 · 측정 전)** 를 따로 내는데, FND 는 둘 다 받고 **PC 로 가는 길에는 값만** 실려서, 오류 · 측정 전에도 PC 는 숫자를 받았다.

| 상황 | FND | 원본 PC | 고친 판 PC |
|---|---|---|---|
| 거리 범위 밖 (Err2) | `Err2` | `400cm` | `Err 2` |
| 거리 무응답 (Err1) | `Err1` | `000cm` | `Err 1` |
| 거리 echo 고착 (Err3) | `Err3` | 직전 거리 숫자 | `Err 3` |
| 온습도 첫 측정 전 | `----` | `00%00C` | `--%--C` |
| 온습도 무응답 · 끊김 · 체크섬 (Err1~3) | `Err1` ~ `Err3` | 마지막 정상값 (없으면 `00%00C`) | `Err 1` ~ `Err 3` |
| 정상 | 숫자 | 숫자 | 숫자 (같음) |

## 2. 신호가 가는 길 — 어디서 상태가 빠졌나

```
SR04 (sr04_core)  ── o_distance (9 비트) ─────────┬──► FND MUX ─► FND        : 값 + 상태 둘 다 감
                  └─ o_status   (2 비트) ─────────┤
DHT11 (dht11_top) ── o_humidity · o_temperature ──┤
                  ├─ o_status (2) · o_dashes (1) ─┤
                  └─ o_led[1] = w_dht_err (1) ────┘
                                                  │
                                                  └──► 송신 MUX (merge_final_top) ─► U_CONTROL ─► uart_sender ─► sender_char_mux ─► FIFO_TX ─► tx
                                                        ▲ 원본 : 값만 실음 (상태 버림)          (24 비트 그대로 잡아 둠)   ▲ 원본 : 숫자 글자만 만듦
                                                        ① 수정 : 상태 비트도 실음                                         ② 수정 : 상태 보고 Err · -- 글자
```

- 송신 데이터 선은 원래부터 **24 비트**인데 거리는 9 비트 · 온습도는 16 비트만 써서 윗비트가 비어 있었다 → 그 빈 자리에 상태를 넣어서 **포트 · 선 폭 · U_CONTROL · uart_sender FSM 은 손대지 않음**.

## 3. 수정 ① — `merge_final_top.v` 송신 MUX (2 줄)

위치 : `merge_final_top.v` 281 ~ 282 줄, `always @(*)` 의 `case (w_send_sel)`

```verilog
// 원본
            3'd3:    w_send_data = {15'd0, w_distance};               // 거리
            3'd4:    w_send_data = {8'd0, w_humidity, w_temperature}; // 온습도

// 고친 판
            3'd3:    w_send_data = {13'd0, w_dist_status, w_distance}; // 거리 + 상태 (fix 10/31, 00 = 정상)
            3'd4:    w_send_data = {4'd0, w_dht_err, w_dht_dashes, w_dht_status, w_humidity, w_temperature}; // 온습도 + 오류 · 측정 전 · 상태 (fix 10/31)
```

- 새 선을 만들지 않았다. `w_dist_status` · `w_dht_err` · `w_dht_dashes` · `w_dht_status` 는 **FND MUX 가 이미 쓰던 선** (238 ~ 239 줄) 을 그대로 가져옴.

24 비트 배치 (sel 3 거리 · sel 4 온습도)

| 비트 | 23 ~ 20 | 19 | 18 | 17 ~ 16 | 15 ~ 11 | 10 ~ 9 | 8 ~ 0 |
|---|---|---|---|---|---|---|---|
| 거리 원본 | 0 | 0 | 0 | 0 | 0 | 0 | 거리 cm |
| 거리 고친 판 | 0 | 0 | 0 | 0 | 0 | **상태** (00 정상 · 01 Err1 · 10 Err2 · 11 Err3) | 거리 cm |

| 비트 | 23 ~ 20 | 19 | 18 | 17 ~ 16 | 15 ~ 8 | 7 ~ 0 |
|---|---|---|---|---|---|---|
| 온습도 원본 | 0 | 0 | 0 | 0 | 습도 | 온도 |
| 온습도 고친 판 | 0 | **err** (마지막 측정 실패) | **dashes** (정상값 아직 없음) | **상태** (01 Err1 · 10 Err2 · 11 Err3) | 습도 | 온도 |

- 온습도 `err` · `dashes` 는 FND 가 `ErrN` · `----` 를 고를 때 쓰는 것과 같은 두 비트 (`FND_LED/fnd_dht.v` 42 ~ 45 줄 : `err` 가 먼저, 아니면 `dashes`). 그래서 **PC 와 FND 가 같은 규칙**으로 갈린다.

## 4. 수정 ② — `UART/sender_char_mux.v` (글자 고르기)

### 4-1. 윗비트를 이름 붙여 꺼냄 (18 ~ 21 줄)

```verilog
    wire [8:0] w_cm   = i_data[8:0];
    wire [1:0] w_dst  = i_data[10:9];   // (fix 10/31) 거리 상태 : 00 정상 · 01 Err1 · 10 Err2 · 11 Err3
    wire [1:0] w_hst  = i_data[17:16];  // (fix 10/31) 온습도 상태 : 01 Err1 · 10 Err2 · 11 Err3
    wire       w_hdash = i_data[18];    // (fix 10/31) 온습도 아직 정상값 없음 (FND "----")
    wire       w_herr  = i_data[19];    // (fix 10/31) 온습도 마지막 측정 실패 (FND "ErrN")
```

### 4-2. 거리 (`3'd3`) — 상태가 00 이 아니면 같은 자리에 `Err N`

```verilog
            3'd3: begin               // 거리 "123cm" + CR LF (7 글자, 0 ~ 6), 오류면 "Err 2" + CR LF (fix 10/31)
                o_last_idx = 6;
                case (i_idx)
                    4'd0: begin
                        if (w_dst != 2'b00) o_char = "E";
                        else                o_char = 8'h30 + w_cm / 100;
                    end
                    4'd1: begin
                        if (w_dst != 2'b00) o_char = "r";
                        else                o_char = 8'h30 + (w_cm / 10) % 10;
                    end
                    4'd2: begin
                        if (w_dst != 2'b00) o_char = "r";
                        else                o_char = 8'h30 + w_cm % 10;
                    end
                    4'd3: begin
                        if (w_dst != 2'b00) o_char = " ";
                        else                o_char = "c";
                    end
                    4'd4: begin
                        if (w_dst != 2'b00) o_char = 8'h30 + w_dst;   // 오류 번호 1 ~ 3
                        else                o_char = "m";
                    end
                    4'd5: o_char = CR;   (원본 그대로)
                    4'd6: o_char = LF;   (원본 그대로)
```

| 글자 번호 (`i_idx`) | 0 | 1 | 2 | 3 | 4 | 5 | 6 |
|---|---|---|---|---|---|---|---|
| 정상 (원본과 같음) | 백 | 십 | 일 | `c` | `m` | CR | LF |
| 오류 (`w_dst` ≠ 00) | `E` | `r` | `r` | 공백 | `1`~`3` | CR | LF |

- 글자 수가 **같아서** (`o_last_idx = 6` 그대로) uart_sender FSM 이 줄 끝을 판단하는 방식은 그대로.

### 4-3. 온습도 (`3'd4`) — 오류면 `Err N`, 첫 측정 전이면 `--%--C`

```verilog
            3'd4: begin               // 온습도 "45%25C" + CR LF (8 글자, 0 ~ 7)
                if (w_herr) begin         // (fix 10/31) 마지막 측정 실패 → "Err 1" + CR LF (7 글자, 거리 오류와 같은 꼴)
                    o_last_idx = 6;
                    case (i_idx)
                        4'd0: o_char = "E";
                        4'd1: o_char = "r";
                        4'd2: o_char = "r";
                        4'd3: o_char = " ";
                        4'd4: o_char = 8'h30 + w_hst;   // 오류 번호 1 ~ 3
                        4'd5: o_char = CR;
                        4'd6: o_char = LF;
                    endcase
                end else begin
                    o_last_idx = 7;              (원본과 같은 8 글자)
                    case (i_idx)
                        4'd0: if (w_hdash) o_char = "-"; else o_char = 8'h30 + w_hum / 10;   // (fix 10/31) 첫 측정 전 → "--%--C"
                        4'd1: if (w_hdash) o_char = "-"; else o_char = 8'h30 + w_hum % 10;
                        4'd2: o_char = "%";
                        4'd3: if (w_hdash) o_char = "-"; else o_char = 8'h30 + w_temp / 10;
                        4'd4: if (w_hdash) o_char = "-"; else o_char = 8'h30 + w_temp % 10;
                        4'd5: o_char = "C";
                        4'd6: o_char = CR;
                        4'd7: o_char = LF;
                    endcase
                end
            end
```

(위 코드는 읽기 쉽게 한 줄로 줄여 적음 — 실제 파일은 원본처럼 `begin` · `end` 로 한 글자씩 나눠 씀)

| 상황 (`w_herr`, `w_hdash`) | 보내는 줄 | `o_last_idx` |
|---|---|---|
| 정상 (0, 0) | `45%25C` + CR LF | 7 (원본과 같음) |
| 첫 측정 전 (0, 1) | `--%--C` + CR LF | 7 |
| 오류 (1, x) | `Err 1` ~ `Err 3` + CR LF | **6** (한 글자 짧음) |

- 오류 줄만 한 글자 짧다 (`Err 1` = 거리 오류 줄과 같은 꼴). `o_last_idx` 는 원래부터 **형식마다 다르게 정하는 출력**이고 uart_sender 는 send_go 순간 데이터를 잡아 두고 (`c_data`) 그 값으로 끝까지 보내므로, 줄 도중에 길이가 바뀌지 않는다.
- 우선순위는 FND (`fnd_dht.v`) 와 같다 : `err` 먼저 → 아니면 `dashes` → 아니면 숫자.

## 5. 손대지 않은 것

| 모듈 | 이유 |
|---|---|
| `UART/01_UART_CONTROLLER.sv` (U_CONTROL) | 24 비트 데이터를 그대로 잡아 sender 로 넘기기만 함 → 윗비트가 늘어도 같음. B-1 을 뺐으므로 이 파일은 원본 그대로 |
| `UART/uart_sender.v` (FSM) | send_go 때 24 비트 · 형식 번호를 잡고 `o_last_idx` 까지 보냄 → 그대로 |
| `uart_top.v` · FIFO · uart_tx | 포트 · 폭 변화 없음 |
| SR04 · DHT11 · FND · LED | 상태 신호는 원래부터 나오고 있었음 (FND 용) → 그대로 |
| XDC | 핀 변화 없음 |

## 6. 확인

| 항목 | 원본 | 고친 판 |
|---|---|---|
| 통합 TB 2 판 (`tb/tb_top_full.v`, 20 시나리오 · 랜덤 명령 120) | 검사 560 · **TOTAL MISMATCH = 0** (`FIX = 0`) | 검사 560 · **TOTAL MISMATCH = 0** (`FIX = 6`) |
| PC 줄 (시뮬) | `00%00C` · `000cm` · `400cm` · 마지막 정상값 | `--%--C` · `Err 1` · `Err 2` · `Err 3` |
| 구현 (Vivado 2022.2 · 100 MHz) | LUT 1,473 · FF 737 · WNS +1.387 ns | LUT 1,489 (+16) · FF 737 · WNS +0.320 ns · 위반 0 |
| 보드 (10/31) | `400cm` · `00%00C` | `Err 2` · `--%--C` · `Err 1` · ECHO 선 뽑음 → FND `Err3` = PC `Err 3` |

- 시뮬 조건 : 시간 단축 파라미터 (UART 115200 bps, `/auto` 500 Hz, 센서 대기 시간 축소 — `2_시뮬검증_가이드` 참고), 클럭 100 MHz 그대로.
- WNS 가 줄었지만 가장 빠듯한 경로는 원본과 같은 **리셋 배선** (U_RESET_SYNC → SR04 카운터 CLR, 로직 0 단) → 배치가 바뀌며 배선이 길어진 것으로 보임 (추정).
- LUT +16 = 글자 고르는 MUX 가 오류 · 측정 전 경우만큼 늘어난 것.
