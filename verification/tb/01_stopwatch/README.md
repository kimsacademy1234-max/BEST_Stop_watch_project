# 01_stopwatch — 스톱워치 검증 기준 (발표: 이종혁)

## 이 기능의 사양 (판정의 기준)

| 버튼 (sw0 = 1, 스톱워치 화면) | 동작 |
|---|---|
| R | 시작 ↔ 정지 |
| L | **정지 상태에서만** 0 으로 지우기 + 랩 해제. 동작 중에는 무시 |
| U | **정지 상태에서만** 업 ↔ 다운 전환. 동작 중에는 무시 |
| D | 랩: 누른 순간 값을 화면에 고정, 다시 누르면 실시간. 내부 카운터는 계속 돈다 |

- 범위 00:00:00.00 ~ 23:59:59.99, 끝에 가면 순환
- 10 ms tick 은 Top 에 하나만 있고(시계 · 타이머와 공용) 항상 흐른다 → 시작 후 첫 증가까지 0~10 ms
- 다른 화면(시계/타이머)으로 바꿔도 계속 돈다. 그 화면의 버튼은 스톱워치로 오지 않는다
- LED: led1 = 스톱워치 화면, led7 = 랩 중

## 공통 판정 방법

- 버튼 1 회 = 5 ms 누름 + 5 ms 뗌. 디바운서 출력 펄스(`wv_btn_pulse`)는 누른 뒤 약 2 ms 에 1 클럭 나온다
- **프리로드**: 59.95 같은 경계 바로 앞 값을 카운터에 직접 넣고 그 직후부터 본다 (주파수는 그대로 100 MHz). 콘솔에 `[INFO][PRELOAD]` 로 시각이 찍힌다
- 콘솔 끝 `[SUMMARY] ... => PASS` 면 이 파일의 모든 기준 통과. `[FAIL]` 줄의 시각으로 파형 이동
- `[LIMIT]` = 사양상 한계를 기록한 것 (FAIL 아님)

### 파형에 넣을 신호
| 신호 | 의미 |
|---|---|
| `btnR` `btnL` `btnU` `btnD` | 버튼 핀 (TB 가 누르는 것) |
| `wv_btn_pulse` | 디바운서 출력 {D,U,L,R} — 실제로 "한 번 눌림"으로 인식된 순간 |
| `wv_sw_run` | 1 = 동작 중 |
| `wv_sw_down` | 1 = 다운 카운트 |
| `wv_sw_lap` | 1 = 랩 표시 중 |
| `wv_sw_hour/min/sec/msec` | 화면에 나가는 값 (랩 중이면 고정값). Radix = Unsigned Decimal |
| `dut.U_STOPWATCH_DATAPATH.w_msec` 등 | 내부 카운터 (랩 중에도 계속 증가) |
| `wv_tick_10ms` | 10 ms tick |
| `led[1]`, `led[7]` | 스톱워치 화면, 랩 |

## tb_sw_1_run_stop_clear.sv — 시작 · 정지 · 지우기

| Phase | TB 가 하는 것 | 정상 동작 기준 | 왜 |
|---|---|---|---|
| P1 | 리셋 | 값 00:00:00.00, 정지(`wv_sw_run` = 0), LED = `000A`(led1 · led3), FND "00.00" | 초기 상태 |
| P2 | R → 정확히 1.000 초 뒤에 정지되도록 R | `wv_sw_run` 이 1 인 구간 = 1000.000 ms(±20 µs), 값 = 1.00 초(count 99~100 허용) | 측정 정확도. 시작 시점과 tick 위상이 무관해서 오차는 최대 1 count |
| P3 | 120 ms 동작 후 정지, 200 ms 대기 | 정지 동안 값이 그대로 | 정지 유지 |
| P4 | 정지 상태에서 D(랩 켬) → L | 랩 켜짐 확인(led7 = 1) 후, L 로 값 0 · 랩 꺼짐, FND "00.00" | 지우기는 정지 상태에서만, 랩도 같이 해제 |
| P5 | 동작 300 ms 중 L, 그다음 U | L 뒤에도 값이 0 이 아니고 계속 증가, 동작 유지 / U 뒤에도 `wv_sw_down` 그대로(업), 계속 증가 | **보드에서 발견된 버그(동작 중 L 이 시간을 지움)의 수정 확인** |
| P6 | 정지 상태(값 있음)에서 R 과 L 을 **같은 순간** 누름 | R · L 펄스가 같은 클럭(`wv_btn_pulse` = 0011) → 동작 시작 + 값 0 부터 | 사양 차이를 `[LIMIT]` 로 기록: 판서 FSM 은 "R 우선, 안 지움" |
| P7 | 동작 중 시계 화면(sw0 = 0)으로 가서 R/L/U/D | 스톱워치는 계속 동작 · 랩 꺼짐 · 업 유지 · 값 증가, 시계 시간도 안 바뀜, LED = `8009`(시계 화면) | 백그라운드 동작 + 버튼 게이팅 |

## tb_sw_2_rollover_updown.sv — 올림 / 빌림 경계

| Phase | TB 가 하는 것 | 정상 동작 기준 | 왜 |
|---|---|---|---|
| P1 | 동작 중 00:00:59.95 프리로드 | tick 4 번 뒤 00:00:59.99 → 5 번째 tick 에 **00:01:00.00** | 초 → 분 올림 |
| P2 | 00:59:59.95 프리로드 | 00:59:59.99 → **01:00:00.00** | 분 → 시 올림 |
| P3 | 23:59:59.95 프리로드 | 23:59:59.99 → **00:00:00.00**, FND(시.분) "00.00" | 24 시간 순환. 4 자리가 한 tick 에 연달아 넘어가는 유일한 순간 |
| P4 | 정지 상태에서 U(다운) → R → 00:00:00.05 프리로드 | `wv_sw_down` = 1, 00:00:00.00 → **23:59:59.99** → 23:59:59.98 | 0 에서 빌림은 업 올림과 조건이 달라서 따로 확인 |
| P5 | 다운 동작 중 U → R(정지) → U → R | 동작 중 U 무시(계속 감소) / 정지 후 U 로 업 전환, 다시 증가 | 방향 전환은 정지 상태에서만 |

## tb_sw_3_lap.sv — 랩

| Phase | TB 가 하는 것 | 정상 동작 기준 | 왜 |
|---|---|---|---|
| P1 | 동작 200 ms 후 D, 100 ms 대기 | `wv_sw_lap` = 1, led7 = 1, **화면 값은 100 ms 동안 고정**, 내부 카운터는 9 count 이상 증가 (100 ms) | 표시와 내부 값이 분리되는 유일한 기능 |
| P2 | 랩 중 D 한 번 더 | 랩 꺼짐, 화면 값 = 내부 카운터 | 실시간 복귀 |
| P3 | 랩 중 동작 상태에서 L → R(정지) → L | 동작 중 L 무시(랩 · 고정값 유지, 내부 안 지워짐) / 정지 후 L 로 랩 꺼짐 + 00:00:00.00 | 동작 중 L 무시 + 지우기의 랩 해제 |
| P4 | 정지 상태에서 D → R | 정지 값이 그대로 고정 표시, 동작을 시작해도 화면은 고정 · 내부만 증가 | 정지 상태 랩 |
| P5 | 동작 중 00:00:59.98 프리로드 직후 D | 랩 값 = **00:00:59.98**, 내부는 00:01:xx 로 넘어감 | 경계 직전 값이 정확히 저장되는지 |
| P6 | 랩 중 FND 확인, sw2 = 1 켜고 시.분 화면 200 ms | FND "SS.CC" = 랩 값, sw2 = 1 이어도 **점멸 없음** ("00.00") | 점멸은 시계 화면 전용 |
