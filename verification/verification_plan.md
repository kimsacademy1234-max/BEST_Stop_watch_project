# 검증 계획서 — Stopwatch / Watch / Timer (merged_v4)

- 대상 설계: `boyun/merged_v4/src` (Top = `stopwatch_watch`)
- 발표 담당: **정안성 = 시계(watch)** · **이종혁 = 스톱워치(stopwatch)** · **정보윤 = 타이머(timer)** · 버튼/FND 공통 TB 는 셋이 같이 인용
- 목적
  1. 기능별 목표를 세우고 Top 시뮬레이션 파형으로 정상 동작을 확인한다 (발표 자료).
  2. 현업에서 생길 수 있는 **환경 결함**을 일부러 넣어, 보드/파형에서 어떤 시각에 어떤 문제가 생기는지 보이고 트러블슈팅 포인트를 제시한다.

## 1. 검증 원칙

| 원칙 | 내용 |
|---|---|
| 주파수 그대로 | clk = 100 MHz 실제 값. 시뮬 시간을 줄이려고 분주 값을 바꾸지 않는다 |
| 시간 점프 | 23:59:59 같은 경계는 카운터 레지스터에 값을 직접 넣고(프리로드) 그 직후부터 본다. 1 초 정확도처럼 "시간 자체"를 재는 검사는 프리로드 없이 실제로 흘린다 |
| 콘솔에 시각 | 이상이 생기면 `[시각] [FAIL]` 또는 `[DEFECT]` 와 내용을 콘솔에 찍는다 → 그 시각으로 파형에서 바로 이동 |
| TB 구성 | 기능당 TB 3 개, 각 TB 는 Phase(P1, P2 …)로 나눠 무엇을 보는지 구분 |
| 결함 | 설계 모듈은 그대로 두고, 결함 주입기를 Top 에 끼워 **sw15** 로 켜고 끈다 (같은 비트스트림에서 정상 ↔ 결함 비교) |

### 버튼 입력의 기준 (모든 TB 공통)
디바운서 = 4 kHz(250 µs) 샘플 8 개가 연속 1 이면 눌림.

| 누름 길이 | 결과 | 이유 |
|---|---|---|
| 1.75 ms 미만 | 무시 | 샘플 7 개 이하 |
| 1.75 ~ 2.0 ms | 누른 시점에 따라 됨/안 됨 | 샘플 위상 |
| 2.0 ms 이상 | 항상 1 번 | 샘플 8 개 보장 |

TB 의 표준 누름 = 5 ms 누름 + 5 ms 뗌.

## 2. 시계 (WATCH) — 정안성

**컨셉**: 리셋 = 오후 12:00:00.00, 12시간 표시. sw2 = 1 이면 설정 모드, 커서(분 일 · 분 십 · 시)로 자리 이동, U/D 로 **그 자리만** ±(윗자리로 올림 없음). 설정 중에도 시계는 흐른다. sw3 = 1 이면 24시간 표시.

### 2.1 경계조건 — 왜 중요한가

| 경계 | 이유 |
|---|---|
| 23:59:59.99 → 00:00:00.00 | 1/100초 · 초 · 분 · 시 4 단 올림이 한 tick 에 연달아 일어나는 유일한 순간. 한 단이라도 틀리면 여기서만 드러난다 |
| 초 59→00(분 +1), 분 59→00(시 +1) | 올림 조건(59 비교)이 맞는지. off-by-one 이 가장 흔한 곳 |
| 설정 wrap: 분 59 +1 → 00, 분십 55 +10 → 05, 시 23 +1 → 0 (윗자리 안 바뀜) | "흐름용 올림"과 "설정용 자리 회전"이 같은 카운터에 있어서 섞이기 쉽다 |
| 12/24 변환: 0시 → 12(오전), 12시 → 12(오후), 13시 → 1(오후) | 0 과 12 가 둘 다 "12"로 보이는 비선형 변환. 부등호 하나로 틀어진다 |
| 1 초 = 정확히 100,000,000 클럭 | 실시간 시계의 정확도 기준 |

### 2.2 체크리스트

| 체크 | 이유 |
|---|---|
| 리셋 직후 12:00, LED = 시계 + 오후 | 보드 켜자마자 보이는 첫 화면 |
| 설정 모드가 아닐 때 버튼 무시 | 실수로 시간이 바뀌지 않게 |
| 설정 진입 시 항상 분 일의 자리부터 | 팀 합의 사양 |
| 커서 L/R 이동과 양 끝 회전 | 커서 FSM 전 경로 |
| U+D 동시 → U 우선 | 설계 사양 |
| 다른 화면(스톱워치/타이머)에서는 시계 버튼 무시, 시계는 계속 흐름 | 버튼 게이팅 |
| 설정 중 커서 자리 점멸 (0.5 초 빈칸) | FND 연동 |
| led15(오후) = 시계 화면 · 12시간 · 12시 이후 | LED 사양 |

### 2.3 입력 / 주기 / 출력 범위

| 항목 | 값 |
|---|---|
| 입력 | 버튼 U/D/L/R (5 ms 누름), sw0 · sw1 · sw2 · sw3 · sw4 |
| 입력 범위 | 커서 0~2, 시 0~23 전부(12/24 표), 분 경계 0 · 9 · 49 · 55 · 59 |
| 주기 | 내부 tick 100 Hz(10 ms), FND 자리 전환 250 µs |
| 출력 범위 | 시 0~23 (표시 1~12 또는 0~23), 분 · 초 0~59, 1/100초 0~99, FND "HH.MM" / "SS.CC" |

### 2.4 TB

Phase 별 자극 · 정상 동작 기준 · 볼 신호: **`tb/03_watch/README.md`**

| TB 파일 | Phase | 파형에서 볼 것 |
|---|---|---|
| `tb/03_watch/tb_wt_1_set_ui.sv` | P1 리셋 · P2 일반 모드 버튼 무시 · P3 커서 이동 · P4 분 ±1 wrap · P5 분십 ±10 wrap · P6 시 ±1 wrap · P7 U+D 동시 · P8 설정 재진입 · P9 다른 화면 버튼 무시 | `wv_wt_cursor`, `wv_wt_min`, `wv_wt_hour`, `btnU/D/L/R` |
| `tb/03_watch/tb_wt_2_rollover.sv` | P1 1 초 정확도 · P2 초→분 올림 · P3 분→시 올림 · P4 자정 23:59:59.99 → 00:00:00.00 · P5 설정 중에도 흐름 | `wv_tick_10ms`, `wv_wt_*` (P4 는 tick 직후 4 클럭 동안 자리별로 0 이 되는 모습) |
| `tb/03_watch/tb_wt_3_display_12h.sv` | P1 시 0~23 × 12/24 표 (48 점) · P2 FND 문자열 · P3 설정 점멸 · P4 LED 표 | `fnd_com`, `fnd_font`, `led[15]`, `wv_wt_msec` |

## 3. 스톱워치 (STOPWATCH) — 이종혁

**컨셉**: R = 시작/정지, L = 지우기(**정지 상태에서만**, 랩도 해제), U = 업/다운 전환(**정지 상태에서만**), D = 랩(누르면 그 순간 값 고정 표시, 다시 누르면 실시간). 00:00:00.00 ~ 23:59:59.99 순환. 다른 화면에서도 계속 돈다.

### 3.1 경계조건

| 경계 | 이유 |
|---|---|
| 업: 59.99 → 다음 초, 23:59:59.99 → 00:00:00.00 | 시계와 구조는 같지만 스톱워치 전용 카운터라 따로 확인 |
| 다운: 00:00:00.00 → 23:59:59.99 | 0 에서 빌려오는 조건은 업 올림과 대칭이 아니다 |
| 시작 후 첫 증가까지 0~10 ms | tick 이 공용(항상 흐름)이라 누른 순간과 tick 위상이 무관 → 측정값 오차 최대 1 count |
| 랩: 표시는 고정, 내부는 계속 증가 | 표시값과 내부값이 분리되는 유일한 기능 |
| **동작 중 L / U 무시** | 보드에서 발견된 버그(동작 중 L 이 잰 시간을 지움)의 수정 확인 |
| 정지 상태에서 R 과 L 을 같은 순간에 누름 → 시작하면서 0 으로 지워짐 | 남아 있는 사양 차이 (설계 한계로 기록) |

### 3.2 체크리스트

| 체크 | 이유 |
|---|---|
| 리셋 → 0, 정지 | 초기 상태 |
| R 시작 / 정지, 정지 중 값 유지 | 기본 동작 |
| 정확히 1.000 초 동작 → 1.00 | 측정 정확도 |
| 정지 상태 L → 0, 랩 해제 | 지우기 |
| 화면을 바꿔도 계속 증가, 다른 화면 버튼은 스톱워치로 안 감 | 백그라운드 · 게이팅 |
| led1, led7(랩) | LED 사양 |
| 스톱워치 화면은 sw2 = 1 이어도 점멸 없음 | 점멸 조건 |

### 3.3 입력 / 주기 / 출력 범위

| 항목 | 값 |
|---|---|
| 입력 | R/L/U/D, 측정 구간 1 초 |
| 입력 범위 | 업/다운 각각, 랩 켬/끔, 동작/정지 각각에서 L · U |
| 주기 | 100 Hz 공용 tick (동작 중일 때만 반영) |
| 출력 범위 | 1/100초 0~99, 초 · 분 0~59, 시 0~23, 랩 0/1 |

### 3.4 TB

Phase 별 자극 · 정상 동작 기준 · 볼 신호: **`tb/01_stopwatch/README.md`**

| TB 파일 | Phase | 파형에서 볼 것 |
|---|---|---|
| `tb/01_stopwatch/tb_sw_1_run_stop_clear.sv` | P1 리셋 · P2 1.000 초 측정 · P3 정지 유지 · P4 정지 중 지우기 · P5 동작 중 L/U 무시 · P6 R+L 동시 · P7 다른 화면에서도 증가 | `wv_sw_run`, `wv_sw_*`, `wv_btn_pulse` |
| `tb/01_stopwatch/tb_sw_2_rollover_updown.sv` | P1~P3 업 올림(초 · 분 · 24시간) · P4 다운 0 → 23:59:59.99 · P5 다운 중 U 무시 → 정지 후 업 복귀 | `wv_sw_down`, `wv_sw_*` |
| `tb/01_stopwatch/tb_sw_3_lap.sv` | P1 랩 고정 · P2 랩 해제 · P3 랩 중 L 무시 → 정지 후 L · P4 정지 상태 랩 · P5 59.98 에서 랩 · P6 FND / 점멸 없음 | `wv_sw_lap`, `wv_sw_*`(표시값), `led[7]` |

## 4. 타이머 (TIMER) — 정보윤

**컨셉**: sw4 = 1 이면 타이머 화면(sw0 보다 우선). 설정: U +10초 · R +1분 · D +10분, **최대 59:59**. L = 시작(0 이면 시작 안 함), 동작 중 L = 취소. 0 이 되면 알람 → LED 16 개 0.5 초 점멸, 타이머 화면에서 아무 버튼 = 끄기. 화면은 항상 "분.초".

### 4.1 경계조건

| 경계 | 이유 |
|---|---|
| 59:50 + U → (60:00 이 아니라) 59:59 | 상한 판정은 초 올림까지 더한 분으로 해야 한다. 빠뜨리면 화면에 60:00 |
| 52:10 + D, 59:xx + R, 59:59 + U → 59:59 | 상한 고정 |
| 00:50 + U → 01:00 | 더하기의 초 → 분 올림 |
| 00:00 에서 L → 시작 안 함 | 0 에서 시작하면 바로 알람이 울리는 것 방지 |
| 01:00.00 → 00:59.99, 10:00.00 → 09:59.99 | 빼기의 빌림 |
| 설정 T 초 → 알람까지 (T − 10 ms, T] | 공용 tick 위상 때문에 최대 10 ms 일찍 끝날 수 있다 (구조상 한계) |
| 알람 끄는 버튼은 더하기로 안 쓰임 | 한 번의 누름이 상태 전환과 동작에 겹쳐 쓰이는지 |

### 4.2 체크리스트

| 체크 | 이유 |
|---|---|
| 타이머 화면 = 분.초 고정 (sw1 무관) | 사양 |
| 동작 중 U/R/D 무시 | 설정에서만 더하기 |
| 다른 화면에서도 계속 감소, 알람은 어느 화면에서나 LED 로 보임 | 백그라운드 |
| 다른 화면 버튼으로는 알람이 안 꺼짐 | 게이팅 |
| sw4 = 1 & sw0 = 1 → 타이머 우선 | 우선순위 |
| led5, led6, 알람 LED 패턴 | LED 사양 |

### 4.3 입력 / 주기 / 출력 범위

| 항목 | 값 |
|---|---|
| 입력 | U/R/D/L, 실제 카운트다운 10 초 |
| 입력 범위 | 00:00 ~ 59:59, 상한 근처 52:10 · 59:00 · 59:50 · 59:59 |
| 주기 | 100 Hz 공용 tick (동작 중일 때만) |
| 출력 범위 | 분 · 초 0~59, 1/100초 0~99, 알람 0/1 |

### 4.4 TB

Phase 별 자극 · 정상 동작 기준 · 볼 신호: **`tb/02_timer/README.md`**

| TB 파일 | Phase | 파형에서 볼 것 |
|---|---|---|
| `tb/02_timer/tb_tm_1_add_cap.sv` | P1 화면/LED · P2 0 에서 시작 안 함 · P3 U×6 → 01:00 · P4 R, D · P5 상한 59:59 · P6 59:59 에서 더하기 · P7 52:10 + D | `wv_tm_min`, `wv_tm_sec` |
| `tb/02_timer/tb_tm_2_countdown_alarm.sv` | P1 10 초 실제 카운트다운(시뮬 약 10 초) · P2 알람 LED 패턴 · P3 D 로 끄기 · P4 빌림 | `wv_tm_run`, `wv_tm_alarm`, `led` |
| `tb/02_timer/tb_tm_3_cancel_background.sv` | P1 동작 중 더하기 무시 · P2 취소 · P3 시계 화면에서 알람 · P4 다른 화면 버튼으로 안 꺼짐 · P5 타이머 우선 | `wv_tm_alarm`, `sw_timer`, `sw_mode`, `led` |

## 6. 결함 주입 — 현업 환경 결함

코드 실수(올림 누락 · off-by-one 등)는 결함 케이스로 넣지 않는다. 그건 위 경계 검사가 잡는다. 여기서는 **설계는 맞는데 보드/환경이 바뀌는 상황**만 다룬다.

공통 방식: 각 폴더 `src/` = 원본 + 결함 주입기 1 개 + Top 연결 몇 줄(줄 끝 `// [FAULT-INJ Fn]`) + xdc 에 **sw15(R2)** 1 줄. sw15 = 0 이면 원본과 같고, 1 이면 결함 상황.

| # | 폴더 | 현업 상황 | 보드 증상 (sw15 = 1) | 파형/콘솔에서 확인 | 해결 방법 | 발표 |
|---|---|---|---|---|---|---|
| F1 | `defect_1_fnd_com_skew` | FND 자리선택(com)이 숫자(data)보다 늦게 바뀜 (트랜지스터 지연 · 배선 스큐) | 각 자리에 옆 자리 숫자가 희미하게 겹침 (12:34 → '4' 자리에 '3') | 자리 전환 순간 `fnd_com` 이 이전 자리에 머무는 동안 `fnd_font` 는 다음 숫자. 지연 5 / 30 / 125 µs 별 잔상 시간 표 | 자리 전환 때 잠깐 모두 끄기(블랭킹) | 공통(정안성) |
| F2 | `defect_2_switch_chatter` | 스위치 노이즈 · 접촉 불량 (누른 중 잠깐 끊김) | U 를 꾹 누르면 분이 저절로 연타, 타이머 +10 초가 여러 번 | `btnU` 가 300 µs 끊긴 뒤 `wv_btn_pulse` 가 또 나옴 → 추가 입력 시각마다 `[DEFECT]`. 짧은 스파이크는 걸러짐 | 뗄 때도 "8 샘플 연속 0" 을 요구 | 공통 + 타이머 |

## 7. 시뮬레이션 방법 (Vivado)

1. **Design Sources**: `boyun/merged_v4/src/*.v`, `*.sv` (결함 TB 는 해당 결함 폴더의 `src/*`)
2. **Simulation Sources**: 보고 싶은 TB 파일 + `verification/tb/common/fnd_monitor.sv` → TB 를 **Set as Top**
3. **Run Simulation → Run All**
4. 콘솔 마지막 줄 `[SUMMARY] ... => PASS / FAIL / DETECTED` 확인. `[FAIL]` 이나 `[DEFECT]` 줄의 시각으로 파형 창에서 이동
5. 한 Phase 만 보려면 TB 맨 위 `RUN_PHASE` 를 그 번호로 바꾼다 (긴 TB 는 꼭)
6. 파형 창에서 `clk` 는 빼고 본다 (수 초 시뮬이면 파형 파일이 매우 커짐). 내부 신호는 `wv_` 로 시작하는 이름으로 TB 최상위에 있다

| TB | 시뮬 시간(대략) |
|---|---|
| tm_2 · F3 | 10 초 · 22 초 → Phase 하나씩 권장 |
| wt_3 · top_1 · top_2 · wt_2 · sw_1 | 2 ~ 3.5 초 |
| 나머지 | 1 초 이하 |

### 콘솔 로그 읽는 법
```
[  1203.450010 ms] [FAIL ] [WT2.P4.WB1] midnight carry | exp=00:00:00.00 got=00:00:59.00 | disp="00.00"
  시각             종류    TB.Phase.검사            무엇을   기대값           실제값            그때 FND 화면
```
| 종류 | 뜻 |
|---|---|
| PASS | Phase 안의 검사가 모두 통과 |
| FAIL | 기대와 다름 → 그 시각 파형 확인 |
| DEFECT | 결함 TB 에서 결함을 잡음 (다음 줄에 파형 볼 구간) |
| LIMIT | 사양상 한계 (FAIL 아님): 바운스 끊김 2 번 입력, R+L 동시 등 |
| INFO | 프리로드 등 참고 기록 |
