# merge_final_top TB 시나리오 (edge case 중심)

- 대상 : `source_file/merge_final/merge_final_top.v` (WTS + SR04 + DHT11 + UART)
- 상태 : **TB 작성 전 시나리오 설계**. 아래 예상 결과는 README 스펙 + 코드 읽고 계산한 값 (시뮬로 아직 확인 안 함)
- 표기 : `P1` 꼭 / `P2` edge / `P3` 견고성 · 여유 있을 때, **⚠** = 코드상 스펙과 다르게 나올 것으로 보이는 항목 ([2 장](#2-설계-이슈-의심--tb-로-먼저-확정할-것))
- 시간 : 전부 **실제 하드웨어 기준** (100 MHz). 시뮬에서 줄여 쓸 때는 [3-3 시간 단축](#3-3-시뮬-시간-단축-defparam) 비율대로 바꿔서 판정

## 3. TB 환경

### 3-1. 구성

```
tb_merge_final_top
├── clk         100 MHz (10 ns)
├── dut         merge_final_top
├── UART BFM    task uart_send_byte / uart_send_str   (9600 bps, 104,167 ns/bit, baud 오차 파라미터)
├── UART 모니터 tx 를 디코드 → 줄 단위 queue {문자열, 시작 시각, 끝 시각}
├── 버튼 task   press(btn, ms) · bounce(btn, n, us) · pulse_phy(btn)  ← w_phy_btn_* 에 1 clk force (정밀 타이밍용)
├── SR04 모델   trig ↓ + ECHO_DLY(0.5 ms) 뒤 echo = 1, W us 유지   (W · 고착 · 글리치 옵션)
├── DHT11 모델  pullup(dht11_io), LOW ≥ 18 ms 감지 → 응답 80/80 us + 40 비트 + 50 us
│               옵션 : 비트 HIGH 길이, 몇 비트 뒤 끊기, 체크섬 오프셋, 무응답, 선 LOW 고착
├── FND 모니터  fnd_com / fnd_font 를 2 ms (8 칸) 모아 "55.24" · "Err1" · "----" 문자열로
└── 스코어보드  check(ID, cond, msg) → [PASS] / [FAIL] + 마지막에 ID 별 합계
```

### 3-2. 판정 공통 규칙

| 항목 | 허용 오차 | 이유 |
|---|---|---|
| 순수 로직 지연 (handshake → 비트 변경, tick → 값 변경 등) | ± 5 clk (50 ns) | 레지스터 단수 |
| 1 us tick 기반 (SR04 · DHT11) | ± 1 us | tick 위상 + 2-FF 동기화 |
| 버튼 (물리 핀 입력) | 1.75 ~ 2.00 ms | 4 kHz 샘플 위상 |
| UART 바이트 | 1 bit = 104.17 us, 1 바이트 = 1.0417 ms | 9600 8N1 |
| UART 응답 시작 | 요청 마지막 바이트 rx_done 뒤 < 0.1 ms | |
| FND 값 읽기 | 값이 바뀐 뒤 2 ms 이상 지나서 읽기 | 한 바퀴 스캔 |

> 시간을 숫자로 박지 말고 TB 안 `localparam` (예 : `T_10MS = F_COUNT_100HZ * 10`) 으로 계산해서 비교하면, 3-3 처럼 줄여도 판정 코드를 안 고쳐도 됨.

### 3-3. 시뮬 시간 단축 (defparam)

`merge_final_top` 은 하위 파라미터를 밖으로 안 내므로 TB 에서 `defparam` 으로 바꿉니다. **실제 기준 시나리오 (특히 D1 · E1 · F1 · H4 · J1 · J9 · J11) 는 원래 값으로 한 번은 돌릴 것.**

| 대상 | 경로 (`dut.` 아래) | 원래 | 권장 시뮬 | 효과 |
|---|---|---|---|---|
| 시계 tick | `U_WTS.U_TICK_GEN_100HZ.F_COUNT` | 1,000,000 | 1,000 | 1 s → 1 ms |
| 스톱워치 tick | `U_WTS.U_TICK_GEN_SW.F_COUNT` | 1,000,000 | 1,000 | 위와 같은 비율로 |
| 타이머 tick | `U_WTS.U_TICK_GEN_TM.F_COUNT` | 1,000,000 | 1,000 | 위와 같은 비율로 |
| auto 주기 | `U_UART.AUTO_FRQ` | 1 (Hz) | 20 (50 ms) | **한 줄 13.5 ms 보다 길게** 둘 것 |
| DHT 부팅 대기 | `U_DHT11.BOOT_CYCLES` | 100,000,000 | 100,000 | 1 s → 1 ms |
| DHT 측정 간격 | `U_DHT11.INTERVAL_CYCLES` | 200,000,000 | 200,000 | 2 s → 2 ms |
| DHT 시작 LOW | `U_DHT11.START_US` | 18,000 | 그대로 (or 1,800) | 줄이면 센서 모델 감지 기준도 같이 |
| SR04 경고 점멸 | `U_SR04.U_LED.BLINK_HALF_CYC` | 25,000,000 | 25,000 | 250 ms → 250 us |

- 4 kHz (디바운스 · FND 스캔) · baud 는 **그대로** 두는 걸 권장 (2 ms · 1 ms 단위라 감당 가능, 바꾸면 BFM 도 바꿔야 함).
- `force` 쓰는 경로 : 스톱워치 `U_WTS.U_STOPWATCH_DATAPATH.U_{HOUR,MIN,SEC,MSEC}_COUNTER.counter_reg`, 시계 `U_WTS.U_WATCH_DATAPATH.U_*_COUNTER.counter_reg`, 버튼 `w_phy_btn_*`. 레지스터는 **force 1 clk → release** 하면 값이 남음.

## 4. 상세 시나리오

각 시나리오 : **왜** (한 줄) → **스티뮬러스** (순서) → **확인** (표, 행 수 = 개수)

### A. 리셋 · 공통

#### A1. 전원 · 리셋 직후 초기값 — `P1` · 7 개

**왜** : 모든 시나리오의 출발점. 여기서 틀리면 나머지 판정이 다 흔들림.

**스티뮬러스**
1. 스위치 전부 0, 버튼 0, `rx` = 1, echo = 0, DHT 모델 대기
2. `rst` = 1 (1 us) → 0
3. 1.2 s 관찰

| # | 확인 | 기대값 | 시간 기준 |
|:-:|---|---|---|
| 1 | `dut.w_rst` 해제 | 0 | rst 하강 뒤 **2 번째** 상승 엣지 |
| 2 | FND | `00.00` (시계 초.1/100, AN2 점) | 해제 + 2 ms |
| 3 | LED | `0x8009` (LD0 시계, LD3 초 화면, LD15 오후 = 12 시) | 해제 직후 |
| 4 | `tx` | 1 (전송 없음) | 1.2 s 내내 |
| 5 | `trig` | 0 | 1.2 s 내내 |
| 6 | `dht11_io` | 1 (Z + pullup) | 1.0 s 까지 |
| 7 | 출력 핀 (`led` `fnd_com` `fnd_font` `tx` `trig`) | x / z 없음 | 해제 + 1 clk 부터 내내 |

#### A2. 동작 중 리셋 — `P1` · 7 개

**왜** : 비동기 리셋이 들어오는 순간 핀이 안전 상태 (tx 1, trig 0, DHT 선 해제) 가 되는지, 모든 FSM 이 처음으로 돌아가는지.

**스티뮬러스**
1. `/mod s_ms` → `/btn R` (스톱워치 RUN), `/auto all`, `/mod dist` → `/btn U` (SR04 auto), `/mod temp` → `/btn R`
2. DHT START LOW 구간 (선 LOW) **이면서** tx 줄 전송 중인 시점에 `rst` = 1 (1 us) → 0
3. 2 s 관찰

| # | 확인 | 기대값 | 시간 기준 |
|:-:|---|---|---|
| 1 | `tx` | 1 | rst ↑ 와 같은 순간 (비동기) |
| 2 | `trig` | 0 | rst ↑ 즉시 |
| 3 | `dht11_io` | 해제 (1) | rst ↑ 즉시 |
| 4 | 제어권 | `w_uart_mode` 0 → 스위치 화면 (시계) | 해제 뒤 |
| 5 | WTS | 스톱워치 0 · STOP, 시계 `12:00:00.00`, 타이머 SET 0 | 해제 뒤 |
| 6 | auto · 센서 | `/auto` 꺼짐 (2 s 동안 줄 없음), SR04 · DHT auto 꺼짐 | 2 s |
| 7 | DHT 부팅 | 다시 1 s 대기 (그 전 START 없음) | 해제 ~ 1.000 s |
